# Six-app ecosystem design: screen-by-screen implementation handoff

**Date:** 2026-09-29
**Figma file:** [Six-app design review](https://www.figma.com/design/N8FPEFodXtdI36vbAOTygl)
**Scope:** Design only. No application source, migrations, paid generation, checkout, scan, provider call, or MOBILE-8F qualification worktree was changed by this design pass.

Start with the [UI inventory and prioritized plan](https://www.figma.com/design/N8FPEFodXtdI36vbAOTygl?node-id=16-5), then the [shared foundations](https://www.figma.com/design/N8FPEFodXtdI36vbAOTygl?node-id=10-3). The approved direction boards remain on page `01 · Direction boards`.

## Evidence and verification

- The user approved the 12 current-state/theme boards before shared components and prototypes were built.
- Current-state visuals come from dated local QA screenshots (mostly 2026-06; XFlow includes a 2026-08 fixture). Source surfaces were inspected on 2026-09-29. Live signed-in review is **MANUAL VERIFICATION REQUIRED** because the in-app browser permission check failed. The `observed` label below means observed in that dated capture, not confirmed current runtime.
- All 48 prototype frames are labeled **PROPOSED DESIGN** and use sample data. Prototype navigation never submits a job, scan, payment, connection, or draft request.
- Figma structural check: 48 frames, 96 primary/alternative click reactions with valid same-page destinations, and desktop/mobile prototype starting points. Mobile title/body/card/button boundaries were checked with no overlaps. Presentation runtime and screen-reader behavior are **MANUAL VERIFICATION REQUIRED**.
- Foundation: 13 reusable components, five semantic color tokens with six Figma brand modes, spacing/type/navigation/form/status guidance. Target [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/); final implementation must test real color pairings, keyboard paths, assistive technology, and zoom.

## Ownership snapshot and conflicts

The ownership ledger and dirty worktrees were rechecked on 2026-09-29 immediately before this handoff. The root MOBILE-8F qualification worktree has untracked qualification scripts, coordination records, and four frozen migrations; the Crevux and Verixet qualification worktrees remain dirty. The ledger records changing exact-file assignments and a suspended shared-schema lease. Recheck the ledger again before assigning implementation. These recommendations grant no write ownership.

- **M8F-C:** Crevux mobile Create/result panels and tests, generation POST, job/asset API, metering, and related ownership are in the MOBILE-8F Crevux qualification scope. Coordinate exact files with that owner before implementing any Crevux screen or XFlow-to-Crevux connection behavior.
- **M8F-V:** Verixet usage ingest, billing usage/credits, diagnostic accounting, and accounting tests are in the MOBILE-8F Verixet qualification scope. Do not implement the limit or upgrade flow in those paths without an owner transfer.
- **M8F-R:** Root `scripts/mobile8f/**` and frozen `supabase/migrations/**` are qualification/schema territory. A later shared package or token implementation must be assigned separately and must leave these paths untouched.

## Screen rows

**Row convention:** Each existing route names a source surface, not proof that the prototype transition works. Every frame is a proposed design. `observed` refers only to dated QA visual evidence; `source-supported` to route/source presence; `proposed` to new behavior or content; `unverified` to a backend or role transition not exercised. Desktop step links and mobile tabs are prototype navigation; the primary and alternative buttons show the specified paths.
